# 로컬 DB 환경

사용자가 요청한 개발자용 PostgreSQL·Valkey·Oracle Free 환경의 검증 기준이다. 특정 명령의 사용법은 [공용 도구](../tools/database/README.md)를 참조한다. (확인)

## 시작·접속·데이터 조작

- 사전 상태: Linux 컨테이너 실행 환경이 준비되어 있고 사용할 포트가 비어 있다.
- 접근 경로: 개발자가 DB를 시작하고 해당 DB의 클라이언트로 테스트 계정에 접속한다.
- 검증 순서: 필요한 DB 선택 → 시작 → 준비 완료 확인 → 테스트 계정 접속 → 임시 값 저장 → 다시 조회 → 임시 데이터 정리.
- 기대 결과: 선택한 DB가 준비 상태가 되고, PostgreSQL·Oracle의 테스트 계정으로 SQL을 실행하며 Valkey에서 키를 읽고 쓸 수 있다. 조회한 값은 저장한 값과 일치한다.
- 결과 확인: 서비스 상태, 명령 종료 코드, 조회값 비교 결과를 확인한다. 검증에 사용한 임시 데이터가 정리되었는지 확인한다.
- 실패 시: 시작·접속·값 비교 중 어느 단계에서 실패했는지 구분하고 로그와 실행 환경을 기록한다.

## 종료·데이터 유지·초기화

- 사전 상태: 이번 검증을 위해 새로 만든 환경이며, 유지할 다른 개발 데이터가 없다.
- 검증 순서: 확인용 데이터 저장 → 환경 종료 → 다시 시작 → 데이터 조회 → 전체 초기화 → 다시 시작 → 기존 데이터 부재와 접속 가능 여부 확인 → 생성한 자원 정리.
- 기대 결과: 일반 종료 후에는 세 DB의 저장 데이터가 유지된다. 전체 초기화 후에는 기존 데이터가 없고 테스트 계정으로 다시 접속할 수 있다.
- 결과 확인: 재시작 전후 조회 결과, 초기화 후 데이터 부재, 정리 후 해당 컨테이너·볼륨 부재를 확인한다.
- 주의: 기존 개발 데이터가 있다면 삭제 검증을 수행하지 않고 해당 항목을 미확인으로 남긴다.

## 검증 경계

이 문서는 로컬 DB 환경의 기준이다. DB 내부 클라이언트의 성공으로 호스트 접속, Rust 드라이버 연결, tlab의 풀·트랜잭션·오류 변환까지 통과로 판단하지 않는다.
각 OS·아키텍처의 실제 실행 여부는 작업별 결과에 기록한다. (확인)
