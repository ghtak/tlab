# 비밀번호 해싱

## 연결 문서

현재 설계는 [비밀번호 해싱 설계](./plan.md)를 참조한다. 관련 기준은 [아키텍처 개요](../../../architecture/index.md), [설정 로딩 명세](../../config/load/spec.md), [공통 에러 요구사항](../../error/requirements.md)을 참조한다.

| 단계 | 상태 | 근거 |

## 목적과 현재 상태

애플리케이션이 비밀번호를 안전하게 해싱하고 저장된 해시와 대조할 수 있는 공통 기능을 제공한다. 요청의 `argone2`, `pdkdf2`는 각각 Argon2, PBKDF2로 해석한다. (추론)

현재 `tlab`에는 알고리즘별 비밀번호 해싱 모듈이 구현되어 있다. 앱 Container는 Argon2id 구현체를 생성·보관하고 로컬 사용자 생성·로그인이 이를 사용한다. 각 구현체는 자체 `Config`를 정의하여 앱 설정과 조합한다. 계정 저장·로그인 정책과 데이터 이전은 소비 기능의 책임이다. 공통 오류는 `tlab::Error`와 `tlab::Result`로 제공한다. (확인: `tlab/src/password.rs`, `tlab-app/src/app.rs`, 가입·로그인 usecase)

## 요구사항과 완료 조건

<a id="req-password-hash-001"></a>
### REQ-PASSWORD-HASH-001: 해시 생성과 검증

- 비밀번호로 저장 가능한 해시를 생성하고, 입력 비밀번호가 저장된 해시와 일치하는지 검증한다. 해시 생성에는 매번 안전한 무작위 salt를 사용한다. (추론: 비밀번호 저장 목적)
- 완료 조건: 각 지원 알고리즘에서 생성한 해시는 올바른 비밀번호로 검증되고 다른 비밀번호는 일치하지 않는다. 반복 생성 시 salt가 달라진다.

<a id="req-password-hash-002"></a>
### REQ-PASSWORD-HASH-002: 알고리즘과 공통 계약

- Argon2와 PBKDF2를 지원하고 호출자가 공통 trait을 통해 해시 생성·검증을 사용할 수 있다. (확인: 사용자 요청)
- 완료 조건: 두 알고리즘 모두 공통 trait 계약으로 사용할 수 있다. 세부 타입과 선택·생성 방식은 설계에서 정한다. (추론)

<a id="req-password-hash-003"></a>
### REQ-PASSWORD-HASH-003: 모듈 설정

- 다른 모듈과 같이 자체 `Config`를 제공하고 앱 설정에 조합하여 설정 로더로 읽을 수 있다. 알고리즘 선택과 필요한 설정의 구체적인 형태는 설계에서 정한다. (확인: 사용자 요청 / 추론: 기존 설정 구조 적용)
- 완료 조건: 설정 로딩을 통해 각 알고리즘을 구성할 수 있고 잘못된 설정은 실패한다.

<a id="req-password-hash-004"></a>
### REQ-PASSWORD-HASH-004: 실패 처리와 비밀 보호

- 잘못된 해시나 지원하지 않는 형식, 해싱·설정 오류는 정상적인 불일치와 구분할 수 있어야 하며 panic 대신 오류를 반환한다. 비밀번호와 해시를 자동으로 로그에 출력하지 않는다. 공통 오류와의 연결 및 세부 분류는 설계에서 정한다. (추론)
- 완료 조건: 불일치와 잘못된 입력·처리 실패를 구분하고 비밀 값이 오류 메시지나 자동 로그에 포함되지 않는지 확인한다.

## 범위와 채택된 기준

- 공통 기능은 `tlab`에 둔다. 회원 가입·로그인, DB 저장, 비밀번호 정책, 기존 계정 데이터 이전은 범위 밖이다. (확인)
- 사용자가 승인한 후속 변경을 포함한 현재 계약과 검증·리뷰 결과는 [설계](./plan.md)를 따른다. 개별 구현체의 설정·검증 책임과 라이브러리 위임, 자체 비용 상한 제거는 사용자 요청으로 채택되었다. (확인)
