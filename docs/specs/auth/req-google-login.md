# 목적

사용자가 별도의 로컬 비밀번호를 만들지 않고 구글 계정으로 앱에 로그인한다. 최초 로그인 시 앱 계정을 생성하고, 이후 같은 구글 계정으로 계속 이용한다. (확인)

# 목표

- 모든 구글 계정 사용자가 구글 로그인으로 앱을 이용할 수 있다. (확인)
- 최초 로그인 시 계정을 생성하고 이후 로그인 시 같은 앱 계정을 사용한다. (확인)
- 웹 로그인 화면에서 구글 로그인을 시작하고, 취소·실패 시 사용자에게 결과를 알린다. (제안)

# 상세

## 요건: 구글 계정으로 로그인

- 동작과 조건: 로그인 화면에서 구글 로그인을 선택하고 구글 인증이 성공하면 앱의 로그인 세션을 시작한다. (제안)
- 합의 상태: 모든 구글 계정 허용은 합의. 웹 화면과 기존 세션 이용은 제안.
- 사용 주체: 앱 사용자, 구글.
- 책임 주체: 구글은 구글 계정 인증 결과를 제공한다. 앱은 인증 결과를 확인하고 앱 계정과 세션을 관리한다.
- 시나리오: 사용자가 구글 로그인을 선택 → 구글 계정 인증 완료 → 앱이 해당 계정을 확인하고 로그인 세션 생성 → 사용자가 앱에 진입한다.
- 제약 및 예외: 인증을 취소하거나 인증 결과를 확인할 수 없으면 로그인하지 않는다. 로그인할 수 없는 상태의 계정에는 기존 계정 정책을 적용한다. (제안)
- 검증 조건: 구글 계정으로 로그인하면 앱에 진입한다. 인증 취소·실패 시 로그인되지 않고 사용자가 결과를 확인할 수 있다. (제안)

## 요건: 최초 로그인 시 계정 자동 생성

- 동작과 조건: 처음 이용하는 구글 계정으로 인증하면 앱 계정과 구글 로그인 수단을 생성한다. 닉네임은 구글 프로필 이름으로 설정하고, 이름이 없으면 `사용자`로 설정한다. (확인)
- 합의 상태: 자동 생성과 닉네임 정책 합의.
- 사용 주체: 처음 로그인하는 사용자.
- 책임 주체: 앱이 구글 사용자를 식별하고 계정 생성과 로그인 수단 등록을 완료한다.
- 시나리오: 처음 보는 구글 계정으로 인증 → 앱 계정과 로그인 수단 생성 → 로그인 세션 시작. 이후 같은 구글 계정으로 로그인 → 기존에 생성된 앱 계정 이용.
- 제약 및 예외: 같은 이메일을 사용하는 로컬 계정이 있어도 자동 연결하지 않는다. 기존 로컬 계정에 구글 로그인 수단을 추가하는 기능은 이번 범위에서 제외한다. 현재 계정 모델의 연결 기준은 [계정 명세](account.md)를 참조한다. (확인)
- 검증 조건: 최초 로그인 후 계정이 생성되고, 재로그인해도 같은 앱 계정이 사용된다. 프로필 이름이 없으면 닉네임이 `사용자`이며, 같은 이메일의 로컬 계정은 연결되지 않는다.

# 가정·미결정 사항

- 적용 대상: 현재 웹 UI를 기준으로 정의했다. 별도 API 클라이언트의 구글 로그인 지원은 미정이며, 필요하다면 해당 클라이언트의 인증 흐름과 결과 계약을 추가로 정의해야 한다. 웹 요구사항의 후속 설계는 진행할 수 있다. (제안)
- 로그인 후 동작: 기존 웹 세션과 로그아웃 정책을 그대로 사용하는 방향이다. 구글 로그아웃까지 연동할 필요가 있는지는 미정이며, 결정에 따라 로그아웃 범위가 달라진다. (제안)
