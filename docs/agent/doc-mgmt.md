# doc-mgmt

현재 설계와 변경 판단에 필요한 내용을 찾고 갱신할 수 있도록 문서 관리. 위치·명명·연결·갱신 기준은 공통으로 적용하고, 출력 양식은 각 스킬에 기반.

## 배치와 연결

- 위치: 관련 주제의 기존 문서 우선. 현재 설계는 `docs/specs`에서 관리.
- 디렉터리: 함께 이해하고 변경할 문서를 같은 디렉터리에 배치. 파일·디렉터리 이름은 대상과 내용이 드러나도록 작성.
- 링크: 설명에 필요한 문서만 본문에서 참조 이유와 함께 연결. 별도 관계 유형·관계 표 및 문서 간 일괄 상호 링크 불필요.
- 개요: 문서가 많아 탐색이 어려울 때만 추가.

## 파일명

- 요구사항: `req-요구사항명.md`.
- 설계·계획: `plan-요구사항명.md`.
- 같은 요구사항의 문서: 동일한 요구사항명에 문서 종류별 prefix 적용.

## 작성과 갱신

- 작성 단위: 목적·책임·함께 변경할 범위를 기준으로 분리·통합. 작업마다 요구사항·계획·검증 문서 세트 생성 불필요.
- 작업 중 기록: 필요한 경우 작성. 제안·가정·미결정 사항은 현재 기준과 구분.
- 현재 설계: 변경 시 관련 문서 직접 갱신. 같은 내용은 한곳에서 관리하고 필요한 곳에서 링크.
- 작업 결과 반영: 현재 설계에 유효한 요구·책임·계약·제약·결정 이유 반영. 중복되거나 대체된 내용은 통합·삭제.
- 과거 경위: Git 이력으로 추적. 현재 판단에 필요한 선택 이유는 본문에 유지.
- 이동·삭제: 관련 링크 함께 정리. 기존 문서 일괄 이전·정제는 필요할 때 수행.

## 출력 양식

- 양식 기준: 각 스킬의 출력 양식 적용. 공통 문서 템플릿은 두지 않음.
- 문체 기준: 저장소 `AGENTS.md`의 `Output Style` 적용. 결론 우선, 개조식·명사형 종결 중심. 사용자·스킬이 특정 표현 방식을 명시한 부분은 해당 지침 우선.
- 관리 항목: ID·상태·메타데이터는 참조·관리 필요가 생길 때 도입.
