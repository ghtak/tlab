# 기능 구상 가이드

## 목적과 범위

요구사항 정의에 앞서 무엇을 지원할지, 각 기능의 범위와 연결은 무엇인지 정리한다.
전체 기능 개요를 유지하면서 개별 요구사항·설계 논의를 별도 대화로 나누어 컨텍스트가 커지는 것을 줄인다. (확인: 사용자 지정 목적)

## 참조와 기록 범위

- 기본은 사용자와의 대화와 일반적인 개념 지식으로 시작한다. 이 가이드와 연결된 기능 구상 스킬 외의 자료는 자동으로 참조하지 않는다.
- 자료는 사용자가 명시적으로 요청한 범위에서 확인한다. 추가 참조가 필요하면 대상·목적을 설명하고 동의 답변을 받은 뒤 확인한다. 이미 허용한 범위는 반복해서 묻지 않는다.
- 앞서 확인한 구현 정보도 사용자가 이번 구상의 전제로 지정하지 않으면 근거로 사용하지 않는다. 사용자 의도·현재 구현·AI 제안을 구분한다.
- 결과는 대화에 유지한다. 저장을 요청받으면 사용자 지정 위치나 `docs/specs/<기능>/index.md` 같은 개요 문서를 사용하고 [문서 관리 규칙](../document-management/index.md)을 해당 범위에 적용한다.
- `docs/notes`는 사용자가 명시적으로 참조를 요청한 문서만 읽으며 확정 요구사항으로 취급하지 않는다. (확인: 사용자 지정 경계·추론)

## 대화 진행

1. **의도 파악**: 목적·대상·지원 범위·제약·나중에 정할 사항을 짧게 정리한다.
2. **기능 개요 정리**: 기능명·한 줄 설명, 선행·의존·공통 관계와 간단한 흐름의 초안을 제시한다.
3. **검토·조정**: 필요성·대안·누락·중복을 살펴 목록과 범위를 조정하고, 별도로 논의할 주제를 정리한다. (제안·추론)

이미 명확한 내용을 다시 묻지 않고, 현재 정보로 초안을 만들 수 있으면 먼저 제시한다.
중요한 질문 한두 개씩 다루며 필요한 단계로 돌아갈 수 있다. 단계별 승인을 강제하지 않는다.
명시된 지원 범위와 새 제안은 구분하고, 필요할 때 `포함·후보·보류·제외`를 표시한다.
보류는 미지원을 뜻하지 않으며, 제안을 확정 요구사항으로 취급하지 않는다. 주요 판단에는 `(확인)`, `(추론)`, `(추측)`을 표시한다. (제안·추론)

## 개요와 개별 논의의 연결

구상 단계에서는 기능 목록, 관계, 열린 질문과 개별 논의의 핵심 결과를 소유한다.
각 기능의 시나리오·정책·예외·검증 조건은 요구사항 논의에서, DB·API·JWT 등의 구체적인 구조와 계약은 설계 논의에서 다룬다. (제안·추론)

상세 논점이 나오면 어떤 기능에 왜 필요한지와 별도로 다룰 질문을 남긴다.
DB나 JWT 같은 기술 이름만으로 작업을 기계적으로 나누지 않고, 목적·소유 책임·함께 결정할 범위를 기준으로 구분한다.
별도 대화를 도구로 자동 생성하지 않으며, 사용자가 요청하면 다음 내용을 짧게 전달한다. (제안·추론)

- 대상 기능과 이번 논의의 목적·포함 및 제외 범위
- 이미 정한 내용과 아직 검토 중인 가정
- 관련 기능과 필요한 연결·제약
- 이번에 결정할 질문과 기대하는 결과

개별 논의의 결과를 전달받으면 핵심 결정·영향·남은 질문과 문서 링크가 있는 경우 그 링크만 개요에 반영한다.
상세 내용을 개요에 복제하거나 하위 문서를 자동으로 모두 읽지 않는다.
상세화 중 전체 범위를 바꿀 필요가 드러나면 개요에서 그 영향을 다시 검토한다. (제안·추론)

## 결과물의 수준

작은 구상은 목록만으로 시작하고, 다음 항목을 필요한 만큼 유지한다. (제안·추론)

| 기능 | 대략적인 범위 | 관련 기능·선행 조건 | 포함·후보·보류 | 별도 논의할 질문·결과 연결 |
| --- | --- | --- | --- | --- |

목적·제약, 주요 흐름과 열린 질문을 함께 적을 수 있다.
상세 시나리오·필드·테이블·API·검증 조건을 채우는 양식으로 확대하지 않는다. (제안·추론)

예를 들어 계정 기능을 구상한다면 사용자 관리·로그인 수단 관리·로그인·토큰 관리의 범위와 연결을 정리할 수 있다.
계정과 로그인 수단의 관계는 개략적으로 논의하되, 저장 구조나 토큰 정책의 상세 논점은 해당 주제에 남긴다.
이는 논의 방식의 예시이며 실제 프로젝트의 확정 기능이나 분할 기준은 아니다. (예시·추론)

기능의 범위·연계성과 별도 논의할 질문이 드러나면 구상 수준에서 마칠 수 있다.
모든 기능의 요구사항이나 설계를 완료하는 것을 종료 조건으로 삼지 않는다. (제안·추론)
