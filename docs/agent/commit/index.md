# 커밋 가이드

커밋은 검증을 마친 뒤 요청하는 별도 작업이다. 커밋 과정에서 테스트·정적 검사·리뷰를 다시 실행하거나 검증 근거를 요구하지 않는다. 변경 범위와 staged diff 확인은 커밋에 포함할 내용을 확인하는 절차로 수행한다.

하나의 작업을 설명하고 되돌릴 수 있는 단위로 커밋한다. 해당 작업의 코드·테스트·관련 spec 문서는 함께 포함하고, 관계없는 변경은 분리한다. 큰 작업은 검증 가능한 단위로 나누며 각 커밋의 문서와 코드가 맞도록 한다.

메시지는 `<유형>: <변경 내용>`으로 작성하고 본문은 이유 설명이 필요할 때만 추가한다.

| 유형 | 용도 |
| --- | --- |
| `feat` | 기능 추가 |
| `fix` | 버그 수정 (`bug` 대신 사용) |
| `refactor` | 동작을 유지하는 구조 개선 |
| `docs` | 문서만 변경 |
| `test` | 테스트만 추가·개선 |
| `chore` | 도구·설정 등 유지보수 |

유형은 작업의 주목적으로 정한다. 기능 추가에 spec·테스트가 포함되어도 `feat` 하나를 사용한다.

```text
feat: 설정 파일 로딩 지원
fix: 빈 설정 경로의 오류 처리 수정
refactor: 공통 오류 변환 로직 통합
docs: 작은 변경 처리 가이드 추가
```
