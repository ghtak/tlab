# Rust 리뷰 선행 검사

## 적용과 실행 위치

- Rust 코드, Cargo 설정·잠금 파일, 빌드·검사 설정, 도구 체인 변경에 적용한다. 문서만 변경되면 `비대상`으로 기록하고 LLM 리뷰로 진행한다.
- 해당 Cargo 워크스페이스 루트에서 실행한다. 변경된 코드의 빌드·검사 범위를 먼저 확인한다.
- 대상 버전·설정·환경이 같은 유효한 기존 결과는 재사용한다. 의존성 검사는 advisory DB 기준·실행 시점도 확인한다.

## 기본 검사

아래 순서로 실행한다. fmt·Clippy는 필수 통과 조건이며 실패·실행 불가이면 후속 검사와 LLM 리뷰를 중단한다. 의존성 audit은 실행·기록 대상이며 결과와 무관하게 LLM 리뷰를 진행한다. 검사 명령은 소스를 자동 수정하지 않는다. (확인: 사용자 지정)

| 순서 | 명령 | 기준과 처리 |
| --- | --- | --- |
| 1 | `cargo fmt --all -- --check` | 종료 코드 0 |
| 2 | `cargo clippy --workspace --all-targets --locked -- -D warnings` | 종료 코드 0, 경고 없음 |
| 3 | `cargo audit` | 종료 코드·advisory·실행 오류를 문서에 기록. 결과는 리뷰를 차단하지 않음 |

- 기본 feature로 검사한다. 변경에 관련된 별도 feature·target이 있으면 지원되는 조합을 명령에 명시하여 추가 검사한다. `--all-features`를 일괄 적용하지 않는다.
- 프로젝트에서 cargo-deny 사용을 명시한 경우 3번을 `cargo deny check advisories` 또는 프로젝트가 지정한 `cargo deny check` 명령으로 대체한다. audit과 같은 목적의 검사를 중복 실행하지 않는다.
- 대체한 의존성 검사도 실행·기록 대상으로 취급한다. audit 결과를 통과로 바꾸거나 advisory를 숨기지 않으며, 결과 자체로 리뷰 중단·점수 미산정·최종 판정 실패를 자동 적용하지 않는다.
- `Cargo.lock`이 없거나 도구 미설치·환경 오류·DB 갱신 실패가 발생하면 `실행 불가`로 기록한다. 잠금 파일 생성·도구 설치가 필요하면 해당 작업의 권한 범위에서 처리하고 다시 실행한다.
- 예외는 프로젝트에 명시된 범위만 적용하고 근거를 남긴다. 검사를 통과시키기 위해 경고·advisory를 임의로 무시하지 않는다.

## 조건부 검사

| 조건 | 호출 명령 | 다음 단계 판단 |
| --- | --- | --- |
| unsafe·메모리 조작·관련 동시성 구현이나 안전성 전제가 바뀌어 실행 검증이 필요한 경우 | `cargo +nightly miri test -p <크레이트> <테스트 필터>` | 대상 크레이트·관련 테스트를 실제 이름으로 지정. 선정된 테스트가 모두 통과해야 LLM 리뷰 진행 |
| unsafe 사용 또는 의존성 변경의 현황 자료가 필요한 경우 | `cargo geiger` | 결과를 LLM 리뷰에 전달. unsafe 개수 자체로 실패 판정하지 않음 |

- Miri가 비대상이면 사유를 기록한다. 실행 대상으로 선정했는데 오류·미지원 동작·환경 문제로 실행하지 못하면 `실행 불가`이며 리뷰를 보류한다.
- Geiger는 참고 자료다. 실행하지 못하면 사유를 기록하되 그 자체로 LLM 리뷰를 차단하지 않는다. 자료가 없는 상태를 unsafe가 없다는 근거로 사용하지 않는다.
- 필요한 기존 테스트는 코드 리뷰 가이드에 따라 별도로 확인한다. 이 선행 검사에 `cargo test`를 일괄 필수 명령으로 추가하지 않는다.

## 진행 판단

| 검사 결과 | 처리 |
| --- | --- |
| 모든 필수 검사 통과, 조건부 필수 검사 통과 또는 비대상 | [LLM 코드 리뷰](index.md)의 리스크·품질 평가 진행 |
| 필수 검사 실패 | `수정 필요`로 검사 결과·필요한 조치 보고. LLM 리뷰 미진행, 품질 점수 미산정 |
| 필수 검사 실행 불가 | `판정 보류`로 실행 조건·필요한 조치 보고. LLM 리뷰 미진행, 품질 점수 미산정 |
| 의존성 audit 실패·실행 불가 | 결과와 원인을 문서에 기록. 다른 필수 검사가 통과하거나 비대상이면 LLM 리뷰·품질 평가 진행 |
| Rust 검사 전체 비대상 | 사유 기록 후 LLM 리뷰 진행 |

리뷰만 요청받았다면 검사 실패를 자동 수정하지 않는다. 도구 결과 해석과 수정 방향은 보고할 수 있다. 수정까지 요청받았다면 리뷰를 차단하는 검사 문제를 해소하고 필요한 검사를 다시 통과한 뒤 LLM 리뷰를 진행한다. audit 실패·실행 불가는 기록 후 리뷰를 계속한다.

## 결과 기록과 재실행

기존 리뷰·작업 문서·CI 기록에 다음을 남긴다.

- 비교 기준과 대상 버전 또는 미커밋 변경 식별 정보.
- 실행 명령, 도구·도구 체인 버전, feature·target·설정. 의존성 검사 시 advisory DB의 식별 가능한 기준과 실행 시점.
- 검사별 상태·문제 요약·필요한 로그 위치, 조건부 검사 비대상 사유와 적용한 예외 근거.
- `LLM 리뷰 진행` 또는 `LLM 리뷰 미진행, 품질 점수 미산정`.

코드·의존성·잠금 파일·설정·도구 체인이 바뀌면 영향을 받는 검사를 다시 실행한다. LLM 리뷰 중 수정한 경우도 동일하게 적용한다. 기존 통과 결과는 변경된 대상의 통과 근거로 그대로 사용하지 않는다.
