# 코드 리뷰 가이드 초안

## 목적과 적용

변경 코드가 요구사항과 계약을 충족하는지 검토하고, 품질 점수와 변경 리스크를 근거와 함께 정리한다.
스코어링, 기능·가독성과 구조·안정성·보안·성능·테스트 용이성 평가, PR 롤백에 의한 복구 가능 여부와 아키텍처 수준의 구조 변경 여부를 다룬다. (확인)

아래 배점·등급·판정 기준은 초기 제안이며, 채택된 운영 기준과 구분한다.
리뷰는 코드·계약·실행 근거로 판단하며, 점수가 높아도 중대한 결함이나 복구 위험을 상쇄하지 않는다. (추론)

## 진행 과정

1. 비교 기준과 대상 커밋, 변경 목적·요구사항·설계, 영향받는 호출자와 데이터 흐름을 확인한다.
2. PR 롤백에 의한 복구 가능 여부와 아키텍처 변경 여부를 확인하여 리스크를 분류한다.
3. 변경과 관련된 기존 코드·테스트를 읽고, 필요한 실행 결과를 확인하여 항목별로 평가한다.
4. 발견 사항의 심각도·근거와 품질 점수·리스크 등급·미확인 범위를 정리한다.
5. 수정 후 발견 사항과 영향받는 항목을 다시 확인하고 대상 커밋·판정을 갱신한다. (추론)

[구현 가이드](../../architecture/guide-impl.md)와 [단위 테스트 가이드](../../architecture/guide-uint-test.md)를 함께 참조한다.
실행 검증은 기존 프로젝트 명령과 CI 결과를 우선 활용하며, 실제 수행하지 않은 검증은 통과로 기록하지 않는다. (추론)

## 품질 점수

각 항목을 0~4점으로 평가하고 가중치를 적용해 100점으로 환산한다.
같은 근본 원인으로 여러 항목에 영향이 있으면 해당 영향을 설명하되 발견 사항은 중복 작성하지 않는다. (추론)

| 항목 | 배점 | 주요 확인 내용 |
| --- | ---: | --- |
| 기능 | 25 | 요구사항·계약 충족, 정상·실패·경계 조건, 기존 동작과의 호환성 |
| 가독성과 구조 | 15 | 이름·흐름의 명확성, 책임과 의존 방향, 기존 구조 활용, 불필요한 중복·추상화 |
| 안정성 | 20 | 오류 처리, 상태 일관성, 동시성, 재시도·중복 처리, 자원 정리 |
| 보안 | 20 | 인증·권한 경계, 입력 처리, 민감정보 노출, 변경된 외부 접근·의존성의 영향 |
| 성능 | 10 | 실제 사용량에 따른 시간·메모리·I/O 비용, 쿼리·반복 호출·자원 사용의 회귀 |
| 테스트 용이성 | 10 | 계약을 검증할 인터페이스, 외부 의존성·상태·시간의 제어, 실패 재현, 의미 있는 기존 테스트 활용 |

테스트 용이성은 테스트 개수나 mock 사용량으로 평가하지 않는다.
테스트 존재 여부뿐 아니라 중요한 실패를 재현하고 계약 위반을 검출할 수 있는지 확인한다.
성능 문제는 코드 경로·계산량·쿼리·측정 등 구체적인 근거로 제시하며 추측만으로 최적화를 요구하지 않는다. (추론)

| 점수 | 기준 |
| ---: | --- |
| 4 | 해당 변경의 주요 조건과 위험이 근거로 확인되며 유의미한 문제가 없음 |
| 3 | 주요 조건을 충족하며 영향이 작은 개선 사항만 있음 |
| 2 | 동작·유지보수·검증에 영향을 주는 보완이 필요함 |
| 1 | 주요 조건에 큰 결함이 있어 수정이 필요함 |
| 0 | 해당 항목의 핵심 계약이 성립하지 않음 |

적용되지 않는 항목은 이유와 함께 `N/A`로 표시하고 적용 항목의 배점 합계로 정규화한다.
판단 근거가 부족하면 `미확인`으로 표시한다. 미확인은 N/A나 0점으로 바꾸지 않으며 최종 총점·통과 판정을 보류한다.
작은 변경에 관련 없는 확인 항목을 억지로 적용하지 않는다. (추론)

`총점 = 100 × Σ(항목 점수 ÷ 4 × 배점) ÷ Σ(적용 항목 배점)`

## 변경 리스크

### 복구 가능성

단방향·양방향은 여기서 변경의 가역성을 뜻한다. 모듈 간 단방향·양방향 의존 관계와 구분한다.
코드 복원 여부뿐 아니라 배포 후 변경된 데이터와 외부 상태까지 고려한다. (추론)

| 분류 | 판단 기준 | 확인할 근거 |
| --- | --- | --- |
| 양방향: PR 롤백만으로 복구 가능 | 이전 코드를 재배포하면 데이터 보정이나 외부 시스템 조치 없이 기존 동작으로 돌아갈 수 있음 | 이전 코드와 현재 데이터·설정·외부 계약의 호환성, 롤백 절차와 검증 결과 |
| 단방향: PR 롤백만으로 복구 불가능 | 데이터 복원·보정, 설정·인프라 복원 또는 외부 조치가 필요함 | 스키마·데이터 변환, 삭제, 외부 발송·결제 등 되돌릴 수 없는 효과와 복구 방법 |
| 미확인 | 복구 가능 조건이나 영향받는 상태를 확인하지 못함 | 추가 확인할 상태·호환성·절차 |

배포 순서·설정·데이터 상태에 따라 복구 가능성이 달라지면 조건을 명시한다.
롤백 명령이 있다는 이유만으로 복구 가능으로 판단하지 않는다.
코드만 읽고 판단한 경우와 실제 롤백을 실행한 경우를 구분하며, 리뷰를 위해 운영 데이터를 직접 변경하지 않는다. (추론)

### 아키텍처 수준의 구조 변경

책임·모듈 또는 서비스 경계, 의존 방향, 데이터 소유권, 주요 인터페이스 계약, 배포 단위나 동기·비동기 처리 방식이 바뀌는지 확인한다.
파일 이동이나 이름 변경만으로 아키텍처 변경으로 분류하지 않고 실제 책임·계약·흐름의 변화를 근거로 판단한다. (추론)

변경 전후의 구성·경계·흐름, 영향받는 호출자·소비자, 호환성과 전환 순서를 정리한다.
관련 `plan.md`와 비교하고 설계와 구현이 다르면 차이와 이유를 기록한다.
필요하면 Mermaid 구성도나 시퀀스 다이어그램으로 경계·흐름 변화를 설명한다. (추론)

### 리스크 등급과 추가 확인

| 복구 가능성 | 아키텍처 변경 없음 | 아키텍처 변경 있음 |
| --- | --- | --- |
| PR 롤백만으로 복구 가능 | R1 | R2 |
| PR 롤백만으로 복구 불가능 | R2 | R3 |
| 어느 축이든 미확인 | 등급 미확정·판정 보류 | 등급 미확정·판정 보류 |

위 표는 기본 등급이다. 데이터 손실, 권한 경계 변경, 광범위한 장애 등 영향이 크면 근거를 적고 R3로 상향한다.
위험이 높은 변경 자체를 결함으로 감점하지 않고, 그 위험을 다루는 구현·검증·복구 방안이 충분한지 평가한다. (추론)

- R1: 변경 범위의 계약과 회귀 위험, 롤백 가능 조건을 확인한다.
- R2: 해당 위험에 따라 복구·보정 절차와 검증 근거 또는 아키텍처 전후 비교·호환성·전환 순서를 확인한다.
- R3: R2 항목에 더해 영향 범위를 제한하는 적용 방법, 이상 관찰 기준, 중단·복구 조건과 실제 복구 가능한 범위를 확인한다. 되돌릴 수 없는 효과는 명시한다. (추론)

## 발견 사항과 판정

발견 사항에는 위치, 발생 조건, 실제 또는 예상 영향, 코드·계약·실행 근거, 필요한 수정 방향을 적는다.
재현하지 못한 문제는 추론 근거와 확인 방법을 명시한다. 취향이나 가정에 따른 개선 의견은 결함과 구분한다. (추론)

| 심각도 | 기준 | 처리 |
| --- | --- | --- |
| 치명 | 주요 데이터 손실·권한 우회·광범위한 장애 등 중대한 영향 | 총점과 관계없이 수정 필요 |
| 주요 | 요구사항·계약 위반 또는 중요한 실패 경로의 결함 | 총점과 관계없이 수정 필요 |
| 경미 | 영향이 제한적인 가독성·구조 등의 개선 사항 | 영향과 우선순위를 기록 |

판정은 다음 순서로 적용한다. 이 기준도 초기 제안값이다. (추론)

1. 치명·주요 발견 사항이 있거나 적용 항목에 2점 이하가 있으면 `수정 필요`.
2. 수정 필요 사항이 없더라도 미확인 항목이나 해당 리스크 등급의 필수 근거가 부족하면 `판정 보류`.
3. 모든 적용 항목이 3점 이상이고 총점 80점 이상이며 리스크 확인을 마쳤으면 `통과`. 그 외는 `수정 필요`.

리뷰 통과는 검토한 범위·커밋에 대한 판단이며 배포 승인이나 모든 실행 경로의 검증 완료를 뜻하지 않는다.
변경된 코드에는 필요한 재검토를 수행하고, 이전 점수·실행 결과를 그대로 최신 근거로 사용하지 않는다. (추론)

## 결과 작성 형태

결과는 PR 리뷰나 작업 문서에 남긴다. 기존 기록을 링크로 참조할 수 있으면 별도 문서를 중복 생성하지 않는다.
리뷰에 따라 설계·구현이 바뀌면 관련 `plan.md`의 본문과 구현·변경 기록을 갱신하고, 세부 실행 근거는 기존 테스트·CI 또는 `verification.md`로 연결한다. (추론)

```markdown
## 코드 리뷰

- 대상: 비교 기준 → 검토 커밋, 변경 목적·범위
- 판정: 통과 / 수정 필요 / 판정 보류
- 품질 점수: 합계 / 100 또는 미확인으로 산정 보류
- 리스크: R1 / R2 / R3 / 미확정, 판단 근거
- 복구 가능성: PR 롤백만으로 가능 / 불가능 / 미확인, 조건·근거
- 아키텍처 변경: 있음 / 없음 / 미확인, 변경된 경계·계약·흐름

### 발견 사항

- [심각도] 파일·위치: 발생 조건 → 영향, 근거, 수정 방향

### 항목별 점수

| 항목 | 점수(0~4 또는 N/A·미확인) | 근거·남은 사항 |
| --- | --- | --- |
| 기능 | | |
| 가독성과 구조 | | |
| 안정성 | | |
| 보안 | | |
| 성능 | | |
| 테스트 용이성 | | |

### 검증과 복구 근거

- 실행한 검증·결과·대상 환경·근거 링크:
- 리스크에 따른 추가 확인·전환·복구 방법:
- 미확인 범위·사유·필요한 확인:
```
