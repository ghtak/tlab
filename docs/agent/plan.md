# plan

요구사항(`req-def` 결과 등) 또는 작업 컨텍스트를 바탕으로 구현할 구조·책임·계약을 설계.

## 진행 원칙

- **질문과 가정:** 목표·책임·호환성 등 설계 방향을 바꾸는 모호함은 핵심 질문 1~2개씩 확인. 영향이 작고 수정하기 쉬운 사항은 가정을 표시하고 진행. 기존 합의 재사용, 단계별 승인 추가 금지.
- **구현과의 경계:** 아키텍처, 모듈 경계, 데이터 구조, 인터페이스 계약까지 설계. 내부 로직은 계약 설명에 필요한 경우에만 포함. 설계만 요청받았다면 구현 코드 작성까지 확장하지 않음.
- **경계와 기존 구조 존중:** 기존 모듈 배치·의존 방향을 검토하고 필요한 범위만 변경. 데이터·판단·행동의 소유권과 구성요소 간 선택·조합·조정의 책임 주체 명시.
- **결정과 근거 기록:** 주요 설계 결정은 `선택안 / 근거 / 검토한 대안`을 짧게 기록하고 관련 코드·문서·실행 결과·사용자 합의 연결. 사실 확인 수준과 제안·합의·미결정 상태는 별도로 구분.

## 1. 설계 목표 및 제약 확인

- 해결할 문제, 기대 동작, 기술적 제약 및 제외 범위(Out of Scope) 확인.

## 2. 현행 구조 파악

- 관련 문서와 현재 코드의 모듈 구조·경계·호출 흐름을 대조. 코드 확인과 실제 실행 검증 구분.
- 문서/코드 불일치 시 실제 동작하는 코드를 우선 기준으로 삼고 문서 갱신 대상으로 표시.
- 기존 코드가 없으면 연결 대상의 계약·제약 확인.
- 저장소의 설계는 [아키텍처 탐색 가이드](../architecture/index.md)에서 관련 구조·개발 가이드를 찾아 적용.

## 3. 대안 검토 및 설계안 도출

- 기존 구조를 활용해 목표를 충족하는 최소안 설계. 중요한 대안이 있을 때 차이·선택 이유 비교.
- 구성요소의 데이터·정책 소유권, 협력 계약과 조정 책임을 기준으로 경계 검토.
- 설계가 목표를 충족하는지 확인할 검증 기준 및 시나리오 정의.

## 4. 설계안 문서화

- 구조·의존 관계의 이해에 도움이 되면 Mermaid 구성도, 호출·상태 변화 순서가 중요하면 시퀀스 다이어그램 사용.
- [문서 관리 가이드](doc-mgmt.md)에 따라 관련 기존 문서 우선 갱신. 사용자 지정 경로·양식 우선.

## 완료 기준

- 목표 충족 방식, 책임·경계·인터페이스 계약, 검증 기준의 연결 확인.
- 주요 결정의 근거와 상태, 가정·미결정 사항의 영향 범위 명시.
- 구현 방향을 바꾸는 중요한 쟁점은 해소하거나 해당 범위를 보류로 표시. 문서 작성만으로 설계 합의·동작 검증 완료로 간주하지 않음.

## 출력 양식

아래 양식 참조. 해당 내용이 없으면 절 생략.

```markdown
# Overview

설계안의 핵심 목표, 해결 방향, 적용 범위 요약.

# Constraints

현행 구조의 한계, 기술적 제약, 사용자 협의 사항 등 설계 전제 조건.

# Key Concepts

후속 설계 이해에 필수적인 핵심 타입, 서비스, 추상화 요소 정리. 간략한 정의 위주 작성 (전체 나열 및 과도한 상세 설명 금지).

# Plan

- **아키텍처 및 경계:** 현재 구조에서 유지·추가·변경할 모듈, 데이터·정책 소유권, 의존 방향과 선택·조합·조정의 책임 주체. 필요 시 Mermaid 다이어그램 포함.
- **인터페이스 계약:** 호출자·제공자, 핵심 타입·시그니처·입출력 구조, 입력 보장과 검증 책임, 오류 의미, 상태 변화·부수 효과. 트랜잭션·재시도·호환성 등은 해당할 때 명시.
- **주요 흐름:** 트리거부터 완료까지의 핵심 실행 시퀀스 (필요 시 시퀀스 다이어그램 포함).
- **변경 대상 및 순서:** 변경 범위를 이해하는 데 필요한 핵심 파일·모듈. 선후 관계가 중요할 때 작업 순서 명시.

# Decisions

- **결정 항목:** 선택안 / 근거 / 검토한 대안. 제안·합의·미결정 상태 구분, 판단에 필요한 근거 위치 연결.

# Assumptions & Open Questions

- 가정·미결정 사항, 영향 범위와 확인할 내용. 중요한 쟁점이 남으면 보류 범위 명시.

# Verification

- 검증 대상과 대응 요건, 적절한 검증 방법·시나리오, 합격 기준. 기존 검증 활용 여부 확인. 설계 시 정한 검증 계획과 실제 실행 결과 구분.
```
