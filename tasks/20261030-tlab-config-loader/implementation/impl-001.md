# Implementation impl-001: 설정 Loader와 공개 계약 검증

## 구현 계획

**목적·선행 조건**

관련 입력은 [요구사항 R1~R9](../requirements.md), [확정 설계](../design.md), [대표 구현 문서](../implementation.md)다. 파일과 접두사 환경변수를 읽어 `config::Config` 또는 호출자 타입으로 반환하는 공개 Loader를 구현한다. 파일과 환경변수에 동일 키가 있으면 환경변수를 우선하며, YAML 검증에는 테스트 전용 구조체를 사용한다.-`측정함`

계획 준비 시점의 `lib.rs`는 `Error`·`Result`와 `add`를 공개하며 설정 모듈은 없다. `error.rs`와 `tests/error.rs`에서 기존 오류 변형과 원인 체인 계약을 확인했다. 현재 Loader 호출자는 검색되지 않았으므로 이 계획에서 이관할 기존 호출부는 없다.-`측정함`

실제 착수 때는 작업 트리를 다시 확인한다. 계획 준비 이후의 사용자 변경과 의존성 해석 가능성을 계획 작성 시점에 확인한 것으로 간주하지 않는다. 계획 준비 당시 요청은 문서 준비에 한정되었다.-`측정함`

**공개 계약과 처리 흐름**

설계에서 확정한 다음 시그니처를 유지한다. 이것은 구현 지시이며 현재 코드가 제공하는 API가 아니다.-`측정함`

```rust
Loader::from_file(path: PathBuf) -> Self
Loader::from_env(prefix: impl Into<String>) -> Self
env_prefix(self, prefix: impl Into<String>) -> Self
load(self) -> crate::Result<::config::Config>
try_deserialize<T: serde::de::DeserializeOwned>(self) -> crate::Result<T>
```

- `Loader`는 비공개 `file: Option<PathBuf>`, `env_prefix: Option<String>`을 소유한다. 생성자는 입력만 보관하고 I/O를 실행하지 않는다. `env_prefix`는 파일 구성을 유지하면서 마지막 접두사로 교체한다.-`추론함`
- `load`에서 파일 소스를 먼저, 환경변수 소스를 나중에 추가해 한 번 빌드한다. 환경 설정은 접두사 구분자 `_`, 계층 구분자 `__`, `try_parsing(true)`를 유지한다.-`측정함`
- 파일을 지정했다면 필수 소스다. config의 탐색으로 파일 소스를 찾지 못하거나 선택한 파일을 읽기·파싱하지 못하면 환경 소스가 있어도 전체 오류로 반환한다. 후보 탐색은 의존성에 위임하며 파일 생성이나 환경변수 단독 재시도는 하지 않는다.-`측정함`
- `try_deserialize`는 `load`를 호출한 뒤 T로 변환한다. 빌드 오류는 원인과 함께 `Error::Internal`로 변환하고, 역직렬화 오류에는 `failed to deserialize config` 문맥을 추가한다. 새 오류 변형·로그·panic은 추가하지 않는다.-`측정함`
- 빈 접두사·빈 환경값·매칭 변수 없음은 설계의 의존성 위임 계약을 유지한다. 새 검증 정책이나 목록 파싱은 추가하지 않는다. 호출자 타입의 필수값 검증은 Serde에 맡긴다.-`측정함`

**변경 범위와 개발 내용**

| 대상 | 계획한 변경 |
| --- | --- |
| `tlab/src/config.rs` 신규 | 위 Loader API와 파일·환경 소스 결합·오류 매핑. 외부 의존성은 `::config`로 참조. |
| `tlab/src/lib.rs` | `pub mod config;` 등록. 크레이트 루트에 Loader를 별도로 재공개하지 않음. |
| `tlab/Cargo.toml` | 아래 확정 의존성 구성 추가. 기존 anyhow·thiserror 유지. |
| `Cargo.lock` | Cargo가 실제 해석한 버전·의존성 기록. 수동으로 버전·checksum을 작성하지 않음. |
| `tlab/tests/config.rs` 신규 | 공개 Loader API와 오류·병합·역직렬화 테스트, 파일·환경 격리용 최소 도우미. |

```toml
[dependencies]
# 기존 anyhow, thiserror 유지
config = { version = "0.15.27", default-features = false, features = ["toml", "yaml"] }
serde = "1"

[dev-dependencies]
serde = { version = "1", features = ["derive"] }
```

위 표와 Cargo 조각은 구현 계획이며 아직 적용하지 않았다. `Error`와 `Result`는 재사용하고 기존 `add`·오류 테스트는 유지한다. 구현·문서·검증에서 계약이 달라지면 근거와 영향을 함께 갱신한다.-`측정함`

**수행 순서와 테스트 격리**

1. 착수 요청 범위·현 작업 트리를 재확인하고 상태와 구현 차수를 기록한다.
2. Cargo 구성, 공개 모듈과 Loader를 연결한다. 생성자·소스 결합·역직렬화는 기존 제시 코드와 설계 범위에 한정한다.
3. `tlab/tests/config.rs`에 아래 완료 조건을 검증하는 외부 호출 관점 테스트를 작성한다. 같은 실패 위험을 중복 테스트하거나 내부 helper 호출 순서를 단언하지 않는다.
4. 저장소 루트에서 대표 문서의 fmt·test·clippy 검사를 실행하고 실패 원인 수정 후 필요한 검사를 재실행한다.
5. 실제 변경·완료 조건별 근거·검증 한계를 개별 문서의 구현 결과에 기록한다. 변경 범위를 확인하고 `feat: impl-001`로 개별 커밋한 뒤 대표 문서를 갱신한다. 사용자 커밋 제외 지시가 있으면 기록하고 따른다.

환경변수 테스트는 현재 통합 테스트 실행 파일의 자식 전용 테스트를 `--exact <이름> --ignored --test-threads=1`로 실행한다. 자식 전용 테스트에는 `#[ignore]`와 부모가 전달한 실행 표시 확인을 두고, 부모가 `Command::env`로 변수를 구성한다. 테스트 접두사의 상속 변수는 자식에서만 제거하며 Windows의 대소문자 차이로 상속 변수가 남지 않도록 한다. 자식 종료 상태를 단언하고 실패 시 출력 근거를 제공한다.-`추론함`

이 방식은 확정 설계의 부모 환경 보존·실제 환경 소스 검증을 구현하기 위한 계획이다. `set_var`·`remove_var`, unsafe, 전역 환경 잠금, 주입용 공개 API는 사용하지 않는다. 시나리오마다 필요한 변수만 전달하며, 자식이 테스트를 하나도 실행하지 않고 성공한 결과를 검증 통과로 취급하지 않도록 실행 대상을 확인한다.-`추론함`

임시 파일은 테스트별 경로에 배타 생성하고 종료 시 정리한다. 없는 파일 테스트의 경로도 테스트 간 공유하지 않는다. 정상 종료 시 정리 실패를 드러내고, 실패 경로에서도 정리하되 이미 처리 중인 panic을 중첩시키지 않도록 도우미를 구성한다. 도우미는 테스트 파일 내부에 두고 새 테스트 의존성·범용 `test_support`는 추가하지 않는다.-`추론함`

### rev-01

**입력과 구현 의도**

사용자가 `implement-task`로 구현 진행을 요청했다. 위 계획과 현재 `tlab` 코드·작업 트리를 대조했으며 Loader는 아직 없고 기존 오류 계약은 유지되어 있다. 기존 스킬 2개와 AGENTS 변경은 보존하고 커밋 범위에서 제외한다.-`측정함`

**구성과 주요 판단**

확정 설계의 생성자 두 개, 파일 다음 환경 소스 결합, 기존 오류 변환을 그대로 구현한다. 실제 공개 API 검증을 위해 환경 테스트는 자식 프로세스로 격리한다. 새 운영 추상화나 테스트 의존성은 추가하지 않는다.-`추론함`

**진행 지점**

중간 기록: Loader, 공개 모듈, Cargo 의존성과 계약 테스트를 작성했다. 최초 기존 테스트 3개는 통과했다. 새 테스트 실행에서는 파일·역직렬화 5개가 통과했지만 환경 테스트의 제외 변수 이름이 실제로 대상 접두사와 일치하여 실패했다. 제외 변수의 접두사 경계를 수정하고 formatter를 적용한 뒤 재검증했으며, 최종 결과는 아래에 기록했다.-`측정함`

사용자가 구현 중 커밋을 진행하지 말라고 지시했다. 스테이징·커밋을 생략하고 미커밋 변경 경로와 검증 근거를 결과에 기록한다.-`측정함`

**실제 변경**

- `tlab/src/config.rs`: `from_file`, `from_env`, `env_prefix`, `load`, `try_deserialize`를 구현했다. 파일 다음 환경 소스를 추가하고 역직렬화 실패 문맥과 원인을 기존 `Internal`에 보존한다.-`측정함`
- `tlab/src/lib.rs`, `tlab/Cargo.toml`, `Cargo.lock`: 공개 config 모듈과 TOML·YAML 전용 config 의존성, serde·테스트 derive를 연결했다. Cargo가 `config 0.15.27`을 해석하여 빌드했다.-`측정함`
- `tlab/tests/config.rs`: 공개 API 파일·YAML·오류 테스트 5개와 환경 계약 부모 테스트, 자식 테스트를 추가했다. 자식에서 접두사 구분·중첩 매핑·숫자/불리언 변환·접두사 교체·환경 우선·파일 전용값 유지·파일 실패 전파를 확인한다. 부모는 자식 성공 표시와 부모 환경 불변을 확인한다.-`측정함`
- 테스트 파일 도우미는 배타 생성한 테스트 디렉터리·파일을 범위 종료 시 정리하며 정상 종료 시 정리 실패를 드러낸다. 기존 `error.rs`, 오류 테스트, `add`는 수정하지 않았다.-`측정함`

**검증과 한계**

실행 위치는 `C:/Users/tlab/works/tlab`, 환경은 로컬 Windows다. 실제 의존성과 파일·환경 소스를 사용했으며 mock을 사용하지 않았다.-`측정함`
