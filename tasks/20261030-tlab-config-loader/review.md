# 전체 작업 리뷰: tlab 설정 Loader

최신 판단(rev-03): 사용자가 config의 탐색 동작을 수용하고 위임 방식으로 되돌리도록 요청했다. 최초 발견 사항 1은 동작 재현 자체는 유효하지만 현재 계약에서는 결함으로 보지 않는다. rev-02의 정확한 경로 제약과 수정 방침은 철회했다. 아래 최초 리뷰·후속 수정 확인은 이력이며 최신 판단은 마지막 절을 참조한다.-`측정함`

## 결과

**보완 필요.** R2의 “지정한 파일이 없으면 오류” 계약을 위반하는 동작 1건을 재현했다. 리뷰 자체는 완료했지만 구현 통과 또는 전체 작업 완료를 의미하지 않는다. 구현자가 수행한 자체 리뷰이며 독립 리뷰가 아니다.-`측정함`

## 비교 기준과 범위

- 기준 커밋은 `0e56a1437e2dc05533be38fa90fed869759addd1`이고, 대상은 해당 HEAD 대비 현재 인덱스와 작업 트리의 config-loader 관련 전체 변경이다. 새 대상 커밋은 없으며 staged·unstaged·untracked 여부를 함께 확인했다.-`측정함`
- 리뷰 시작 시 코드·작업 문서와 기존 스킬·AGENTS 변경이 staged 상태였다. 관련 코드의 별도 unstaged 차이는 없었다. 리뷰 중 기존 인덱스를 수정하지 않았고 스테이징·커밋하지 않았다. 이전 구현 결과의 “스테이징 없음”은 구현 종료 당시의 기록으로 보존한다.-`측정함`
- 검토한 코드 변경은 `Cargo.lock`, `tlab/Cargo.toml`, `tlab/src/lib.rs`, `tlab/src/config.rs`, `tlab/tests/config.rs`다. 기존 `tlab/src/error.rs`, `tlab/tests/error.rs`와 Loader 호출부를 함께 읽었다.-`측정함`
- 작업의 요구사항·설계·대표 구현 문서·개별 구현 결과·상태를 검토했다. 별도 작업인 `.agents/skills/implement-task/SKILL.md`, `.agents/skills/new-feature/SKILL.md`, `AGENTS.md` 변경은 이 기능 리뷰 범위에서 제외했다.-`측정함`
- 동작 범위는 동기 설정 로딩과 호출자 타입 역직렬화다. 요구되지 않은 부하 목표나 자동 재로딩 요구는 추가하지 않았다.-`측정함`

## 발견 사항

### 1. [P2] 없는 파일 대신 다른 파일을 읽어 성공함

**위치**

[`tlab/src/config.rs:41`](../../tlab/src/config.rs#L41), 기존 없는 파일 테스트는 [`tlab/tests/config.rs:83`](../../tlab/tests/config.rs#L83) 부근이다. 관련 계약은 요구사항 R2와 설계의 필수 파일 실패 경계다.

**근거와 재현**

`Loader::from_file(path)`는 `config::File::from(path)`에 파일 찾기를 위임한다. 설치된 `config 0.15.27`의 `src/file/source/file.rs`에서 `find_file`을 확인했다. 지정 경로가 파일이 아니면 지원 확장자를 덧붙인 경로를 탐색하고, 그 파일이 있으면 사용한다. `required: true`는 이런 탐색 결과까지 없을 때만 오류를 낸다.-`측정함`

임시 디렉터리에 아래 상태를 만든 뒤 현재 빌드된 tlab을 연결한 임시 Rust 실행 파일에서 공개 API로 재현했다. 저장소 코드·테스트·설정은 변경하지 않았다.-`측정함`

```text
settings.toml       없음
settings.toml.yaml  내용: name: unexpected-fallback
```

```rust
assert!(!requested.exists());
let config = Loader::from_file(requested.clone()).load().unwrap();
assert_eq!(config.get_string("name").unwrap(), "unexpected-fallback");
```

실제 출력은 `requested_exists=false; load=Ok; name=unexpected-fallback`이었다. 임시 소스와 실행 파일·설정 파일은 `TemporaryDirectory` 종료 시 정리했다.-`측정함`

**영향**

지정 파일이 없어도 오류 대신 다른 설정을 적용해 실행할 수 있다. 따라서 호출자는 요청한 파일이 읽혔다고 잘못 판단할 수 있다. 기존 없는 파일 테스트는 대체 후보가 없는 디렉터리만 사용하므로 이 위반을 발견하지 못한다.-`추론함`

**해결 방향**

지정 경로가 없으면 소스 빌드 전에 오류로 반환하도록 보장하거나, 확장자 탐색 없이 정확한 경로 내용을 읽는 방식으로 변경한다. `required(true)`만 추가해도 현재 탐색 동작은 유지되므로 해결되지 않는다. `settings.toml`은 없고 `settings.toml.yaml`만 있는 경우에도 `Error::Internal`이어야 하는 회귀 테스트를 추가한다. 제시 코드의 `File::from(PathBuf)` 유지와 R2가 충돌하므로 구현 보완 시 설계의 파일 소스 설명도 함께 갱신해야 한다.-`추론함`

리뷰 요청 범위에 따라 수정은 수행하지 않았다. 후속 구현 보완 대상은 `impl-001`이며, 재작업을 시작할 때 해당 구현과 전체 구현 상태를 `progress`로 되돌리고 새 차수에 이 발견 사항의 처리·재검증 결과를 남긴다.

## 미확인 사항과 인계

- Windows에서 확인했다. Linux·macOS 실행, OS 파일 권한 오류 재현, 외부 취약점 데이터베이스 점검, 별도 독립 리뷰는 수행하지 않았다.-`측정함`
- R1·R3~R9의 구현과 기존 검증 근거에서 추가 확정 결함은 찾지 못했다. 모든 가능한 입력이나 환경의 무결함을 보장하는 판단은 아니다.-`측정함`
- 리뷰 산출물은 이 문서와 `state.json`의 리뷰 항목이다. 코드·테스트·Cargo 설정·기존 구현 결과와 인덱스는 수정하지 않았고 커밋도 하지 않았다.-`측정함`
- 발견 사항 1을 구현 보완과 회귀 검증에 연결한 후 재리뷰한다. 현재 리뷰 결과는 `보완 필요`다.

## 후속 확인: rev-02의 발견 사항 1 수정

사용자가 발견 사항 1의 구현 보완을 요청하여 수정과 회귀 검증을 수행했다. 이번 확인 범위는 해당 발견 사항과 파일 읽기 경계 변경의 영향이며 독립 리뷰는 아니다.-`측정함`

지정 경로는 `std::fs::read`로 직접 읽고 파일 내용만 명시적 형식으로 `config::File::from_str`에 전달한다. 기존 `find_file` 경로 탐색은 호출하지 않는다. 존재 여부 선검사만 추가하는 방식과 달리 이후 후보 파일을 선택하는 경로 자체가 제거됐다.-`측정함`

신규 회귀 테스트는 수정 전 `Ok`를 반환하여 실패했고, 수정 후에는 파일 단독·환경 결합 모두 `Internal`로 실패하는 것을 확인했다. `.yml`·BOM, 지원하지 않는 형식과 기존 TOML·YAML·오류·환경 계약 검증을 포함해 전체 테스트 12개와 부모를 통한 자식 테스트가 통과했다. fmt·Clippy 검사도 다시 실행해 통과했다. 상세 명령과 해시는 rev-02에 기록했다.-`측정함`

후속 확인 결과: **요청 범위 충족.** 발견 사항 1은 수정 및 회귀 검증을 완료했다. 최초 리뷰의 `보완 필요`는 rev-01 당시 판단이며 현재 수정 확인으로 대체한다. 코드 전체에 대한 새로운 독립 리뷰나 다른 OS 검증을 수행한 것으로 해석하지 않는다.-`측정함`

## 계약 재검토와 위임 복원: rev-03

사용자가 정확한 경로 제약의 필요성을 재검토했고 config에 위임하는 방향으로 복원하도록 요청했다. R2는 지정 경로의 부재 자체가 아니라 config의 탐색으로 설정 소스를 찾지 못할 때 오류를 반환하는 계약으로 갱신했다.-`측정함`

최초 리뷰는 제시 코드와 테스트에서 도출한 R2를 지나치게 엄격한 경로 제약으로 해석하고 구현 결함으로 분류했다. 실제로는 의존성의 탐색 동작과 추가 제약 사이의 계약 선택 문제로 설명했어야 했다. 기존 동작 재현·검증 사실은 보존하되 결함 분류와 정확한 경로 읽기 권고는 현재 계약에 따라 철회한다.-`추론함`

`File::from(path)`와 rev-01 테스트를 복원했고 별도 파일 읽기·확장자 판별·BOM·디코딩 구현과 관련 추가 테스트를 제거했다. 복원 후 전체 기본 테스트 9개와 부모를 통한 자식 테스트, fmt·Clippy 검사를 다시 실행해 통과했다. 상세 근거는 [rev-03](implementation/impl-001.md#rev-03)에 기록했다.-`측정함`

최신 결과는 **요청 범위 충족**이다. 발견 사항 1은 현재 계약에서 추가 수정이 필요하지 않다. 이번 확인은 사용자 결정에 따른 계약·구현·검증 정합성 확인이며 새로운 독립 리뷰는 아니다. 스테이징·커밋은 수행하지 않았다.-`측정함`
