# Implementation impl-001: 오류 처리

## 목적·선행 조건

[설계](../design.md)의 `Error`와 `Result`를 공개하고 기존 `add`를 유지한다.

## 완료 조건과 검증

| 조건 | 확인 방법 |
| --- | --- |
| 두 오류 변형과 별칭의 외부 사용 | 통합 테스트 |
| 표시, 변환과 원인 체인 | 통합 테스트 |
| 기존 기능 유지 | cargo test |

## 구현 결과

### rev-01

**입력과 구현 의도**

설계에 따라 구현한다. 착수 시 Cargo.toml, Cargo.lock, 작업 문서와 무관한 스킬 및 gitignore에 기존 변경이 있었다. 사용자 지시로 스테이징과 커밋을 생략한다.

**구성과 주요 판단**

비공개 `error` 모듈에서 타입을 정의하고 루트에서 재공개했다. 기존 의존성을 재사용했으며 `anyhow`의 원인 체인을 표준 `Error::source`로 전달한다.

**실제 변경**

- `tlab/src/error.rs`, `tlab/src/lib.rs`: 설계의 오류 변형과 별칭을 구현하고 재공개했다.
- `tlab/tests/error.rs`: 외부 공개 계약을 검증했다.
- 미커밋 변경은 `git -c safe.directory=C:/Users/tlab/works/tlab diff`와 미추적 파일을 함께 확인한다. 경로만으로 당시 코드를 복원할 수는 없다.

**검증과 한계**

저장소 루트에서 `cargo fmt --all`, `cargo test -p tlab`을 실행했다. 최초 테스트는 source 첫 단계가 root라는 잘못된 기대 때문에 실패했고, context와 root의 두 단계를 확인하도록 수정한 뒤 단위 테스트 1개와 통합 테스트 2개가 통과했다. Cargo는 경로 canonicalize 경고를 출력했다.

**완료 조건 확인과 인계**

| 조건 | 근거 |
| --- | --- |
| 외부 오류 계약 | 통합 테스트 통과 |
| 표시, 변환, 원인 체인 | 통합 테스트 통과 |
| 기존 기능 | 기존 단위 테스트 통과 |

사용자 지시로 스테이징과 커밋을 생략했다. 기존 미커밋 변경을 유지했다.

### rev-02

**입력과 구현 의도**

[리뷰](../review.md)의 입력별 표시 검증 누락을 확인했다. 기존 테스트는 두 기대값을 OR로 묶어 리뷰 지적이 타당하다. 각 입력에 대응하는 출력만 허용하도록 수정하고 테스트를 재실행한다. 착수 시 기존 작업과 무관한 스킬 및 gitignore 변경이 미커밋 상태다. 사용자 지시에 따라 커밋과 스테이징을 생략한다.

**구성과 실제 변경**

`tlab/tests/error.rs`에서 정적 문자열과 소유 문자열 각각에 기대 표시 문자열을 연결하여 정확히 비교한다. 공개 구현은 변경하지 않았다. 미커밋 파일은 `git status --short`와 `tlab/tests/error.rs`를 확인한다. 미추적 파일 경로만으로 당시 내용을 복원할 수는 없다.

**검증과 완료 조건**

저장소 루트에서 `cargo test -p tlab`을 실행해 단위 테스트 1개와 통합 테스트 2개가 통과했다. 최초 `cargo fmt --all -- --check`는 파일 끝 빈 줄 때문에 실패했고 `cargo fmt --all` 후 재검사에 통과했다. Cargo는 경로 canonicalize 경고를 출력했다. 입력별 정확한 표시 검증과 기존 오류 변환·원인 체인 및 `add` 테스트를 확인했다. 전체 워크스페이스 테스트는 실행하지 않았다.

커밋과 스테이징은 사용자 지시로 생략했다. 리뷰 지적은 반영했으며 별도의 재리뷰는 수행하지 않았다.
