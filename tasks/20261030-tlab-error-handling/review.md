# 작업 리뷰

## 범위와 기준

기준은 HEAD `35c71b8257f3854bdf287a098369cc3f174cbcd3`이다. 작업 대상의 미커밋 `Cargo.lock`, `tlab/Cargo.toml`, `tlab/src/lib.rs`, 미추적 `tlab/src/error.rs`, `tlab/tests/error.rs` 및 작업 문서를 검토했다. 무관한 스킬과 `.gitignore` 변경은 제외했다. 독립 리뷰가 아닌 구현자의 자체 리뷰다.

## 발견 사항

### 테스트의 입력별 표시 검증이 약함

`tlab/tests/error.rs`의 `invalid_parameters_support_static_and_owned_messages`는 각 입력에서 두 출력 중 어느 하나만 일치해도 통과한다. 예를 들어 두 입력 모두 `invalid parameter: static`을 반환하는 결함을 탐지하지 못한다. 설계가 각각 전달된 설명을 표시하도록 요구하므로 입력별 기대 문자열을 짝지어 비교하는 것이 적절하다. 현재 구현은 설계와 일치하며, 이는 테스트의 회귀 탐지 한계다.

## 검증과 결과

요구사항, 설계, 구현과 테스트 및 의존성 diff를 확인했다. 동일 코드에서 실행한 `cargo test -p tlab`의 단위 1개와 통합 2개 통과 결과를 재사용했다. 추가 실행은 하지 않았다. 전체 워크스페이스 테스트는 확인하지 않았다.

결과: **보완 필요**. 공개 구현 자체의 계약 위반은 발견하지 못했으나 입력별 표시 계약을 테스트가 충분히 확인하지 못한다. 리뷰 완료는 구현 승인이나 전체 작업 완료를 뜻하지 않는다.

## 재검토: rev-02

기준은 동일한 HEAD `35c71b8257f3854bdf287a098369cc3f174cbcd3`이며, 작업 범위의 미커밋 추적 파일과 미추적 구현·테스트 및 작업 문서를 다시 확인했다. 무관한 사용자 변경은 제외했다. 구현자의 자체 리뷰다.

이전 발견 사항은 처리됐다. `tlab/tests/error.rs`가 정적 문자열과 소유 문자열 각각을 대응하는 기대 출력과 비교하므로, 한 출력이 두 입력에 공통으로 반환되는 회귀를 탐지한다. 요구사항과 설계의 공개 타입, 변환, 표시 및 기존 기능을 다시 대조했으며 추가 발견 사항은 없다.

저장소 루트에서 `cargo test`를 실행해 단위 테스트 1개와 통합 테스트 2개가 통과했고 문서 테스트는 0개였다. 앞서 실행한 `cargo fmt --all -- --check` 통과 결과도 재사용했다.

결과: **요청 범위 충족**. 리뷰 완료는 전체 작업 완료나 머지·배포 승인을 뜻하지 않는다.
