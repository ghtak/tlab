# 초기 설계

요구사항을 구현하는 데 필요한 구조와 근거를 작업 디렉터리에 기록한다.

1. 플레이북이나 호출자가 지정한 작업 디렉터리와 요구사항을 확인한다. 작업 디렉터리가 불분명하면 임의로 선택하지 말고 확인한다.
2. 관련 코드와 문서를 조사해 기존 동작, 구조와 재사용 가능한 기능을 파악한다. 확인한 사실과 가정, 미확인 사항을 구분한다.
3. 사용자가 요구한 결과와 호출 방식부터 정하고 필요한 입력·출력, 책임과 경계, 데이터 흐름을 설계한다. 기존 기능과 의미상 중복을 확인하고 요구사항에 필요한 구조만 제안한다.
4. 구조 선택이 결과에 큰 영향을 미칠 때만 실질적인 대안을 비교한다. 각 선택의 이유와 제약을 명시하고 확인되지 않은 필요를 위해 추상화하지 않는다.
5. 작업 디렉터리의 `design.md`에 요구사항 요약, 관련 기존 구조, 제안 구조와 인터페이스, 선택 근거, 확인이 필요한 사항을 간결하게 기록한다. 필요한 내용만 포함하고 기존 문서가 있으면 내용을 확인한 뒤 갱신한다.
6. `state-mgmt`로 설계 작업을 등록하거나 기존 작업을 갱신하고 `design.md`를 연결한다. 주요 결정이나 변경 이유는 필요할 때 `task-log`로 기록한다. 상태와 문서 내용은 실제 진행 상황에 맞춘다.

구현 중 동일한 우회나 예외 처리가 반복되면 설계의 전제와 요구사항을 다시 확인하고, 필요한 변경과 근거를 문서에 반영한다. 설계는 구현 완료나 검증 통과를 뜻하지 않는다.
