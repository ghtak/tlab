# 간단한 개발 작업

작은 기능이나 국소적인 수정을 대화로 진행하고 작업 디렉터리의 `work.md`에 필요한 내용만 기록한다.

## 단계 진행

각 단계의 결과와 다음 단계를 사용자에게 보여주고 종료한다. 사용자가 대화에서 다음 단계의 진행을 명시적으로 요청한 후에만 해당 단계를 수행한다. 일반적인 동의나 새 정보가 진행 지시인지 불명확하면 확인한다. 한 번에 여러 단계를 명시적으로 요청했다면 요청한 범위까지 진행한다.

1. **요청 확인**: 요청, 목적과 완료 기준을 정리하고 관련 코드와 기존 동작을 확인한다. 결과를 `work.md`에 기록한다.
2. **구현 방향**: 필요한 변경 범위와 검증 방법을 간결히 정리한다. 결과를 기록하고 사용자에게 제시한다.
3. **구현·검증**: [guideline-coding](../guideline-coding/SKILL.md)을 적용해 구현하고 변경한 동작을 실제 실행해 확인한다. 실제 변경, 검증 결과와 미확인 사항을 기록한다.
4. **리뷰·결과**: 전체 변경과 관련 호출부를 확인해 요청과의 정합성, 발견 사항과 검증 근거를 정리한다. 보완이 필요하면 결과를 보고하고 사용자 지시에 따라 구현 단계로 돌아간다.

## 상태와 기록

- 새 작업이면 [state-mgmt](../state-mgmt/SKILL.md)로 작업 디렉터리를 만들고, 기존 작업이면 지정된 디렉터리를 사용한다. `quick_change` 작업을 등록하거나 조회해 `work.md`에 연결한다.
- `work.md`에 요청·구현 방향·주요 결정·변경·검증·리뷰 결과, 현재 단계와 다음 행동을 간결히 기록한다. 기존 기록을 보존하고 실제 수행과 제안을 구분한다. 별도 단계별 문서나 작업 분할은 요구하지 않는다.
- 수행 중 상태는 `progress`, 구현·검증·리뷰와 필요한 보완을 마쳤을 때만 `complete`로 기록한다. 중단 시 이유와 재개 조건을 남긴다.
- 재개 시 `state.json`, `work.md`와 실제 변경을 확인한다. 대기 중인 단계는 사용자의 명시적인 진행 요청을 받은 후 수행한다.
- 커밋은 사용자가 명시적으로 요청한 경우에만 수행하며, 요청한 범위와 형식을 따른다. 다른 사용자 변경을 포함하지 않는다.
- 작업이 여러 독립 변경으로 커지거나 별도 설계·인계가 필요해지면 `new-feature` 전환을 제안하고 사용자 지시를 기다린다.
