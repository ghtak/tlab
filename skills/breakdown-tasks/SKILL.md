# 작업 분할

1. 플레이북이나 호출자가 지정한 작업 디렉터리와 요구사항을 확인하고, 설계 문서가 있으면 필요한 부분을 읽는다. 관련 코드와 기존 테스트도 확인한다.
2. 합의한 범위를 구현과 검증이 가능한 결과 단위로 나눈다. 작은 작업을 형식적으로 분할하지 않고, 함께 변경해야 동작하는 부분은 묶는다.
3. 작업 디렉터리의 `tasks.md`에 작업 ID, 목적과 범위, 필요한 입력·선행 결과, 관찰 가능한 완료 조건과 검증 방법을 기록한다. 실제 선행 관계와 공유 변경 영역, 통합 방법은 필요한 경우에만 명시한다. 순서와 의존성을 상태 파일에 넣지 않는다.
4. 재개·인계 또는 개별 상태 추적에 필요하면 `tasks/<task-id>.md`로 개별 작업을 분리하고 `tasks.md`에서 연결한다. 각 문서에 관련 계약과 코드 경로를 참조하고, 확인되지 않은 경로나 명령은 추측하지 않는다.
5. 범위의 누락·중복과 선행 조건을 확인한다. 핵심 계약이 불명확하면 확인이 필요한 내용을 남긴다.
6. `state-mgmt`로 분할 작업을 등록하거나 갱신하고 `tasks.md`를 연결한다. 각 구현 작업을 `pending`으로 등록하고 개별 문서가 있으면 해당 문서를, 없으면 `tasks.md`를 연결한다. 기존 작업은 확인한 뒤 갱신한다. 분할 완료는 구현 완료를 의미하지 않는다.
