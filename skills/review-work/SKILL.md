# 전체 작업 리뷰

작업에 속한 전체 변경을 검토한다. 개별 Task의 구현 검증과 전체 변경 리뷰를 구분한다.

1. 플레이북이나 호출자가 지정한 작업 디렉터리와 리뷰 대상을 확인한다. PR 또는 작업의 비교 기준과 대상 커밋, staged·unstaged·untracked 변경의 포함 여부를 식별한다. 다른 작업이나 사용자 변경을 자동으로 포함하지 않으며 범위가 불명확하면 확인한다.
2. 필요한 요구사항·설계·Task 문서와 구현 및 검증 결과를 읽는다. 문서가 없으면 합의된 요청과 실제 코드·계약을 근거로 검토한다.
3. 전체 diff와 필요한 관련 코드·호출부·테스트·설정을 확인한다. 요구사항과의 정합성, Task 간 연결, 오류 처리, 데이터 정합성 및 변경에 따른 실제 위험을 검토한다. 근거 없는 우려를 결함으로 확정하지 않는다.
4. 동일한 코드와 조건에서 유효한 기존 검증 결과를 재사용하고 필요한 검사만 추가로 실행한다. 실행 결과와 확인 범위를 구분하고 실패, 실행 오류와 미실행 사유를 기록한다. 필수 검사를 완료하지 못하면 통과로 표시하지 않는다.
5. 작업 디렉터리의 `review.md`에 비교 기준과 대상, 검토·검증 범위, 발견 사항의 위치·근거·영향·해결 방향, 미확인 사항과 결과를 기록한다. 결과는 `요청 범위 충족`, `보완 필요`, `판단 보류` 중 실제 결과에 맞게 표현한다. 기존 결과가 있으면 덮어쓰지 않고 재검토 범위와 이전 발견 사항의 처리 결과를 추가한다.
6. `state-mgmt`로 리뷰 작업을 등록하거나 갱신하고 `review.md`를 연결한다. 리뷰 수행과 결과 기록을 마쳤으면 발견 사항이 남아 있어도 리뷰 작업을 `complete`로 기록할 수 있다. 리뷰 완료는 구현 통과, 전체 작업 완료 또는 머지·배포 승인을 의미하지 않는다.

리뷰만 요청받았다면 코드·테스트·설정을 수정하지 않는다. 전체 작업 수행에 보완이 포함된 경우 발견 사항을 구현 작업으로 연결하고 수정의 영향 범위를 재검토한다. 자체 리뷰를 독립 리뷰로 표시하지 않는다.
