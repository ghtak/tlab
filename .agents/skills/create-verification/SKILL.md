# 앱 수준 검증 구성

앱을 직접 조작하고 결과를 관찰하여 기대 결과와 비교할 수 있는 도구·문서를 마련한다.
사용자가 요청한 구성·실행 범위와 기존 검증 자산을 우선한다.

## 참조 문서

경로는 이 `SKILL.md`가 있는 디렉터리를 기준으로 해석한다.

- 시작할 때 [앱 수준 검증 도구·방법 구성 가이드](../../../docs/agent/create-verification/index.md)를 읽고 적용한다.
- 작업 문서를 작성·갱신할 때 [문서 관리 규칙](../../../docs/agent/document-management/index.md)의 저장 위치·식별자·상태·연결 규칙을 적용한다.
- `docs/notes`와 가이드에서 연결한 정리 메모는 사용자가 명시적으로 참조를 요청한 문서만 읽는다. 읽은 메모를 확정 요구사항으로 간주하지 않는다.

## 수행

1. 실제 사용 경로와 검증할 계약·기대 결과를 확인하고, 기존 도구·기능 정의·검증 문서를 재사용한다. 가이드의 예시 명령을 실제 도구로 가정하지 않는다.
2. 부족한 앱 조작·상태 관찰 수단을 필요한 범위에서 보완한다. 공용 도구와 실제 사용법은 `docs/verification/tools/`에 둔다.
3. 도구와 독립적인 기능별 접근 경로·검증 순서·기대 결과·확인 방법은 `docs/verification/feature/`에 정리한다.
4. 작업별 `verification.md`에 검증 범위, 준비·격리, 실제 도구 명령, 관찰·판정·정리 방법을 작성한다. 공용 정의와 사용법은 링크로 연결한다.
5. 구성 확인은 핵심 기능부터 실제 준비·조작·관찰·판정·정리까지 수행한다. 실패는 근거로 원인을 확인하여 보완하고, 실행할 수 없으면 사유와 미확인 범위를 남긴다.

행동 수행 여부와 기대 결과 충족 여부를 구분한다. 실행하지 않은 검증은 통과로 기록하지 않는다.
실행이 만든 자원만 정리하고 검증 근거를 보존한다. 다른 실행의 데이터·세션·프로세스를 건드리지 않는다.
방법 정리만 요청받았다면 실제 실행 결과와 구분하여 보고하며, 실행을 완료하지 않은 상태를 구성 확인 완료로 처리하지 않는다.
