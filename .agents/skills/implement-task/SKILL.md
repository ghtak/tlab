# 작업 구현

1. 지정된 작업 디렉터리와 대상 작업, 요구사항·설계·작업 문서 및 관련 코드와 선행 결과를 필요한 만큼 확인한다. 범위나 필수 계약이 불명확하면 확인한다.
2. `state-mgmt`에서 대상 상태를 확인하고 실제 착수 시 `progress`로 변경한다. 기존 사용자 변경과 커밋에 포함할 범위를 확인한다.
3. [guideline-coding](../guideline-coding/SKILL.md)을 적용해 합의된 범위를 구현한다. 테스트를 선택하거나 작성할 때 [guideline-testing](../guideline-testing/SKILL.md)을 따르고, 변경한 동작과 필요한 연결 동작을 실제 실행해 검증한다.
4. 대상 작업 문서에 실제 변경, 주요 판단, 실행한 검증과 결과, 실패·미검증 사항을 간결히 기록한다. 별도 검증 결과 문서가 있다면 중복 대신 경로와 요약을 남긴다. 개별 작업 문서가 없으면 작업 디렉터리의 `tasks.md`에 기록한다.
5. 완료 조건과 변경 범위를 확인한 후 해당 구현의 변경만 스테이징하고 `feat: task-xxx` 형식으로 개별 커밋한다. `task-xxx`는 실제 작업 ID로 대체한다. 무관한 사용자 변경을 포함하지 않는다. 커밋할 변경이 없거나 커밋할 수 없으면 이유를 보고한다.
6. 커밋 해시를 작업 결과에 기록하고 `state-mgmt`에 문서를 연결한다. 구현과 필요한 검증이 완료됐을 때만 `complete`로 변경한다. 완료되지 않았다면 현재 상태와 이유를 기록한다. 커밋 해시를 적은 기록은 자기 자신의 커밋에 포함될 수 없으므로 후속 커밋에 포함하거나 작업 디렉터리에 남긴다.

결과 재진행 시 이전 변경·검증 근거를 보존하고 새 결과를 추가한다. 구현 완료는 전체 작업이나 리뷰 완료를 의미하지 않는다.
