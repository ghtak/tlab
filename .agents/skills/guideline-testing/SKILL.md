# 테스트 지침

테스트는 요구사항과 계약에 따른 동작이 깨졌을 때 실패하도록 구성한다.

- 테스트할 계약과 기대 결과를 먼저 정하고, 호출자가 사용하는 함수·API·CLI·UI 등 적절한 인터페이스를 통해 검증한다. 현재 구현의 결과를 그대로 기대값으로 삼지 않는다.
- 반환값, 오류, 공개 상태와 의미 있는 부작용을 확인한다. 내부 구현만 바뀌고 계약이 유지되면 테스트도 유지되도록 한다.
- 내부 helper의 호출 순서·횟수나 중간 자료구조는 계약상 필요할 때만 확인한다. 세밀한 경계값이나 내부 수준 테스트는 실제 요구, 위험 또는 재현된 결함에 근거해 추가한다.
- 기존 테스트가 같은 동작과 실패 위험을 검증하면 재사용하거나 보완한다. 자명한 구현이나 같은 실패를 반복 확인하기 위해 테스트를 추가하지 않는다.
- 프로젝트의 기존 테스트 명령과 공통 환경을 우선 사용한다. 외부 의존성의 실제 동작이 계약에 중요하면 격리된 실제 환경에서 확인하고, mock 결과를 실제 연동 검증으로 보고하지 않는다.
- 변경과 위험에 맞는 검증을 선택한다. 실행한 명령·결과와 확인 범위를 기록하고, 실패·실행 오류·미실행을 구분한다. 테스트 수나 일률적인 커버리지 수치를 목표로 삼지 않는다.
