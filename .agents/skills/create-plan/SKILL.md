# 설계 문서 작성

기존 구조를 활용하는 최소안을 제시하고 대화를 통해 구현할 구조와 계약을 구체화한다.
사용자의 명시적인 요청과 이미 합의된 진행 방식을 우선한다.

## 참조 문서

경로는 이 `SKILL.md`가 있는 디렉터리를 기준으로 해석한다.

- 시작할 때 [설계 문서 작성 가이드](../../../docs/agent/create-plan/index.md)를 읽고 적용한다.
- 설계 시 [구현 가이드](../../../docs/architecture/guide-impl.md)와 [테스트·검증 가이드](../../../docs/architecture/guide-test.md)를 읽고 구현 방향과 검증할 계약·기대 결과에 반영한다.
- 작업 문서를 작성·갱신할 때 [문서 관리 규칙](../../../docs/agent/document-management/index.md)의 저장 위치·식별자·상태·연결 규칙을 적용한다.
- `docs/notes`는 사용자가 명시적으로 참조를 요청한 문서만 읽는다. 읽은 노트를 확정 요구사항으로 간주하지 않는다.

## 수행

1. 관련 요구사항·설계·현재 소스에서 기존 구조와 변경 범위·제약을 확인한다. 별도 요구사항 문서가 없으면 대화에서 기준을 정리한다.
2. 요구사항을 충족하는 최소안을 제시하고, 중요한 대안·선택 이유·미결정 사항을 논의한다. 이미 합의한 내용은 재사용하고 단계별 승인을 추가하지 않는다.
3. 구성요소의 책임·분리 경계·의존 방향·주요 흐름과 인터페이스 계약을 구체화한다. 주요 결정·가정에는 근거와 확인 수준, 합의 상태를 구분한다.
4. 해당 작업의 `plan.md`에 설계를 작성·갱신하고 가이드의 완료 기준으로 점검한다. 구현·변경 기록은 하단에 발생 순서대로 보존하고 세부 검증 근거는 링크로 연결한다.

설계만 요청받았다면 설계 산출물까지 수행한다. 후속 구현도 요청받았다면 합의한 범위와 남은 제약을 이어서 적용한다.
