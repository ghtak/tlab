# 요구사항 정의

이번 범위의 설계·구현계획에 전달할 수 있는 요구사항을 정리한다.
사용자의 명시적인 요청과 이미 합의된 진행 방식을 우선한다.

## 참조 문서

경로는 이 `SKILL.md`가 있는 디렉터리를 기준으로 해석한다.

- 시작할 때 [요구사항 정의 가이드](../../../docs/agent/requirements-definition/index.md)를 읽고 적용한다.
- 요구사항 문서를 작성할 때 [작성 양식](../../../docs/agent/requirements-definition/template.md)을 읽고 작업 규모에 맞게 사용한다.
- 작업 문서를 작성·갱신할 때 [문서 관리 규칙](../../../docs/agent/document-management/index.md)의 저장 위치·식별자·상태·연결 규칙을 적용한다.
- `docs/notes`는 사용자가 명시적으로 참조를 요청한 문서만 읽는다. 읽은 노트를 확정 요구사항으로 간주하지 않는다.

## 수행

1. 사용자 요청, 기존 요구사항과 관련 결정을 확인하여 이번 작업 범위와 산출물을 파악한다. 기존 문서가 있으면 재사용하고 부족한 부분을 보완한다.
2. 가이드에 따라 목적·사용 방식, 시나리오, 세부 기능, 요구사항·검증 조건, 누락·우선순위를 정리한다. 이미 명확한 내용은 묶어서 진행한다.
3. 중요한 미결정 사항은 영향과 선택지를 제시하여 확인한다. 영향이 작은 가정은 표시하고 진행하며, 사용자가 요청하지 않은 단계별 승인 절차를 추가하지 않는다.
4. 가이드의 완료 기준으로 결과를 점검한다. 정리한 요구사항, 중요한 결정·가정, 남은 미결정 사항과 다음 진행 가능 여부를 보고한다.

요구사항 정의만 요청받았다면 산출물 정리까지 수행한다. 구현계획이나 구현도 요청받았다면 해당 요청 범위에 맞춰 후속 작업으로 연결한다.
