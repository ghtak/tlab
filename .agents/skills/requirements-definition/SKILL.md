# 요구사항 정의

선택한 기능의 동작과 충족 조건을 설계·구현에 전달할 수 있는 수준으로 정리한다.
사용자의 명시적인 요청과 이미 합의된 진행 방식을 우선한다.

## 참조 문서

경로는 이 `SKILL.md`가 있는 디렉터리를 기준으로 해석한다.

- 시작할 때 [요구사항 정의 가이드](../../../docs/agent/requirements-definition/index.md)를 읽고 적용한다.
- 기본은 사용자와의 대화로 시작한다. 이 스킬과 가이드 외의 스킬·저장소·내부 문서·외부 자료는 자동으로 참조하지 않는다. 앞서 확인한 구현 정보도 사용자가 이번 작업의 전제로 지정하지 않으면 근거로 사용하지 않는다.
- 사용자가 참조를 명시적으로 요청하면 지정한 범위에서 확인한다. 자료 확인이 필요하다고 판단하면 대상·목적을 설명해 질문하고, 동의 답변을 받은 뒤 확인한다. 같은 범위의 허락은 반복해서 묻지 않는다.
- 사용자가 문서 저장·갱신을 요청한 경우에는 [작성 양식](../../../docs/agent/requirements-definition/template.md)과 [문서 관리 규칙](../../../docs/agent/document-management/index.md)을 읽고 해당 범위에 적용한다.
- `docs/notes`는 사용자가 명시적으로 참조를 요청한 문서만 읽는다. 읽은 노트를 확정 요구사항으로 간주하지 않는다.

## 수행

1. 대상 기능의 목적·범위·제약과 전달받은 결정·열린 질문을 확인한다. 기능 구상 문서를 필수 선행 조건으로 요구하지 않는다.
2. 사용자 행동·시스템 반응·기대 결과를 시나리오로 정리하고, 정책·예외·관찰 가능한 검증 조건을 구체화한다.
3. 누락·모호함과 중요한 미결정 사항을 검토한다. 전체 기능 범위를 바꾸는 논점은 개요에 반영할 질문으로 남기고, 다른 기능이나 설계로 상세 논의를 넓히지 않는다.
4. 정리한 요구사항과 남은 가정·제약을 전달한다. 문서 저장은 요청받은 경우에 수행하며, 설계·구현은 해당 요청이 있을 때 진행한다.

이미 합의한 내용을 반복해서 묻거나 단계별 승인을 요구하지 않는다. 자료를 참조한 경우 사용자 요구·현재 구현·AI 제안을 구분한다.
