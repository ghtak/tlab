# 코드 리뷰

대상에 맞는 도구 검사를 먼저 수행하고 리뷰 진행 조건을 충족하면 LLM 리뷰로 결함·품질 점수·변경 리스크·미확인 범위를 보고한다. 의존성 audit은 실행하고 결과를 문서에 기록하되 실패·실행 불가로 LLM 리뷰를 차단하지 않는다.
사용자가 지정한 대상·평가 기준을 우선하며, 리뷰만 요청받았다면 코드 수정까지 범위를 넓히지 않는다.

## 참조 문서

경로는 이 `SKILL.md`가 있는 디렉터리를 기준으로 해석한다.

- 시작할 때 [코드 리뷰 가이드](../../../docs/agent/code-review/index.md)를 읽고 항목별 기준·리스크 분류·결과 양식을 적용한다. 배점·등급·통과 기준은 가이드의 초기 제안 상태를 유지하며, 합의된 기준이 있으면 우선한다.
- Rust 코드·의존성·빌드 및 검사 설정 변경은 [Rust 선행 검사](../../../docs/agent/code-review/deterministic-rust.md)의 명령과 진행 조건을 적용한다. 문서만 바뀐 경우에는 Rust 검사를 비대상으로 기록한다.
- [구현 가이드](../../../docs/architecture/guide-impl.md)와 [테스트·검증 가이드](../../../docs/architecture/guide-test.md)를 읽고 변경과 검증 근거를 평가한다.
- 작업 문서를 작성·갱신할 때 [문서 관리 가이드](../../../docs/agent/doc-mgmt.md)를 적용한다.
- `docs/notes`는 사용자가 명시적으로 참조를 요청한 문서만 읽는다. 읽은 노트를 확정 요구사항으로 간주하지 않는다.

## 수행

1. 비교 기준과 검토 대상 버전·차이, 변경 목적·계약, 관련 호출자·데이터 흐름·기존 테스트를 확인한다. 커밋하지 않은 변경이면 검토한 diff와 상태를 식별한다.
2. 대상에 해당하는 선행 검사 문서를 읽고 명령을 실행한다. 같은 대상·설정·환경의 유효한 기존 결과는 재사용한다. 리뷰를 차단하는 필수 검사가 실패하거나 실행 불가이면 결과와 필요한 조치를 보고하고 LLM 리뷰·점수 산정은 진행하지 않는다. 의존성 audit 결과는 성공·실패·실행 불가를 그대로 문서에 남기고 리뷰를 계속한다. 리뷰만 요청받았다면 코드를 자동 수정하지 않는다.
3. 리뷰를 차단하는 필수 검사가 모두 통과하거나 비대상이면 LLM 리뷰를 진행한다. PR 롤백만으로 데이터·설정·외부 상태까지 복구 가능한지, 책임·경계·계약·주요 흐름이 바뀌는지 확인한다. 복구 가능성과 아키텍처 변경을 별도 축으로 평가하고 리스크 근거·필요한 복구 조건을 기록한다.
4. 발견 사항을 위치·발생 조건·영향·근거·수정 방향과 심각도로 정리한다. 재현한 사실과 코드에서 도출한 판단을 구분하고 취향이나 추측을 결함으로 제시하지 않는다.
5. 여섯 품질 항목을 근거로 평가한다. 적용되지 않는 항목은 이유와 함께 N/A, 근거 부족은 미확인으로 두고 가이드에 따라 총점과 판정을 산정한다. 도구 통과 자체를 만점 근거로 사용하거나 높은 점수로 중대한 결함을 상쇄하지 않는다.
6. 발견 사항을 먼저 보고하고 품질 점수·리스크·판정, 선행 검사 결과와 수행한 검증·미확인 범위를 함께 남긴다. 수정 후에는 변경 영향을 받는 선행 검사를 다시 확인한 뒤 재리뷰한다.

기존 테스트·CI·`verification.md`의 근거는 검토한 버전·범위와 대조한다. 롤백 절차가 있다는 이유로 실제 복구를 검증했다고 판단하지 않는다.
리뷰 결과는 기존 PR·작업 문서에 연결하고 불필요한 별도 문서를 만들지 않는다. 외부 게시·전송은 사용자 요청 범위에서만 수행한다.
