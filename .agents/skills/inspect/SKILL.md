# 조사 (Inspect)

사용자가 궁금해하는 대상을 근거에 따라 조사하여 이해와 후속 판단에 필요한 설명을 만든다.
사용자의 질문과 범위를 우선하며, 조사만 요청받았다면 대상 수정이나 새 설계로 범위를 넓히지 않는다.

## 참조 문서

경로는 이 `SKILL.md`가 있는 디렉터리를 기준으로 해석한다.

- 시작할 때 [조사 가이드](../../../docs/agent/inspect/index.md)를 읽고 적용한다.
- 프로젝트 구조를 조사할 때는 [아키텍처 개요](../../../docs/architecture/index.md)를 활용하고 실제 상태는 관련 원본과 대조한다.
- 결과를 작업 문서에 보존할 때만 [문서 관리 규칙](../../../docs/agent/document-management/index.md)의 해당 규칙을 적용한다. 단순 질문에는 별도 문서를 만들지 않는다.
- `docs/notes`는 사용자가 명시적으로 참조를 요청한 문서만 읽으며, 확정 요구사항으로 간주하지 않는다.

## 수행

1. 질문과 조사 대상·범위, 필요한 근거 수준을 파악한다. 영향이 작은 모호함은 해석을 밝히고 진행하며, 결론을 크게 바꾸는 불명확한 대상·환경은 확인한다.
2. 질문에 맞는 원본·관찰 자료에서 구성·흐름·관계·조건을 추적한다. 작은 질문은 직접 조사하고, 넓은 질문은 필요한 관점으로 나눈다.
3. 중요한 주장에 문서 위치·파일·설정·로그·실행 결과 등 근거를 연결한다. 자료 간 모순은 적용 범위·버전·조건과 원본을 대조하고 미해결 부분을 남긴다.
4. 디버깅에서는 증상·재현 조건·기대와 실제 결과를 구분하고, 원인 후보를 구별할 관찰·검증으로 범위를 좁힌다. 분석 요청만으로 수정까지 진행하지 않는다.
5. 질문에 대한 답을 먼저 제시하고 필요한 개념·흐름·관련 위치·주의점을 설명한다. 자료에서 읽은 사실, 실행·관찰로 확인한 결과, 추론·추측을 구분한다.
6. 가이드의 완료 기준으로 점검하고 결론에 영향을 주는 미확인 사항과 후속 확인 방법을 보고한다. 후속 요구사항·설계·수정에서는 조사 근거와 제안·결정을 구분한다.
